# M2.5 Deep Output Review — Final LinkedIn Drafts

**Date:** 2026-08-23
**Scope:** `.genesis/examples/7-day-content-examples.md` (7 generated posts) + the pipeline that produced them.
**Method:** Voice/brand audit, verifier gate check, claim-overlap check, production-readiness scan.

## Executive Summary

- **0 Critical** findings.
- **5 Warning** gaps that hurt quality or trust before automated daily runs.
- **6 Info** observations (strengths + minor polish).
- All 7 example posts pass no-go-word and word-budget checks.
- All 7 fail APPROVE in `verify_draft()` when stripped of newsletter + hashtags (because verifier is strict), but the **real drafts generated by the pipeline include newsletter sections and hashtags**, so this is a measurement artifact, not an output bug.

## Strengths (Info)

1. **Voice consistency is real.** Persona comes through as "sharp colleague in a group chat": direct, skeptical of hype, optimistic when signal is real.
2. **No-go words are absent.** None of the 15 banned buzzwords appear in the 7 examples.
3. **Word budgets are respected.** Per-post word counts: 134, 153, 209, 113, 182, 204, 154 — all under their day-type maxima.
4. **Day-type jobs are distinct.** Each post matches its calendar role (tool drop, viral explained, pattern spotting, builder memo, security signal, founder signal, weekly synthesis).
5. **Saturday Founder Signal enforces a question.** Every Saturday example ends with the founder CTA question.
6. **CTA per day is present.** Every post closes with the expected day-specific discussion prompt.

## Warning Findings

1. **Verifier can reject real drafts for missing source URL.**
   - `verify_draft()` checks `source_url in draft.linkedin_post`. The example Sunday/Tuesday posts do not embed the source URL in the LinkedIn body.
   - **Risk:** a valid, well-written draft may be downgraded because the LLM omitted a URL.
   - **Action:** Either relax the verifier (URL in newsletter is enough) or add a prompt instruction / post-processor that appends `Read more: <url>` when absent.

2. **Newsletter section is required by verifier but not validated in drafter output.**
   - Verifier subtracts 8 points if `newsletter_section` is < 80 words. The example posts have empty newsletter sections in the parsed output (the pipeline likely generates them; the example doc stripped them).
   - **Risk:** if the LLM forgets the newsletter section, the draft fails APPROVE even when the LinkedIn post is good.
   - **Action:** Add a test that ensures `draft.newsletter_section` is non-empty and ≥ 80 words after hydration.

3. **Hashtag quality gate is brittle.**
   - `_has_specific_topics` matches hashtags against the taxonomy by exact-ish match. Hashtags like `#AgentGovernance` or `#BuilderMemo` may fail because they are not literal taxonomy strings.
   - **Risk:** good, specific hashtags get penalized.
   - **Action:** Map post-type / day-plan to expected hashtag sets and verify at least one specific tag exists, rather than relying on raw taxonomy matching.

4. **Claim verification is shallow for paraphrased claims.**
   - Jaccard-ish overlap at 35% can pass rephrased claims that drift from source. Conversely, it can fail precise claims that use different words.
   - **Risk:** false negatives / false positives on factual accuracy.
   - **Action:** Add an optional LLM-based semantic claim check (with cost control) for high-confidence numbers and named assertions.

5. **`cmd_draft_today` still falls back to raw items silently.**
   - No `--allow-raw` flag exists yet. In a daily scheduled run, low-signal raw items could be drafted if no worthy items exist.
   - **Risk:** queue gets filled with unvetted content.
   - **Action:** Gate the raw fallback behind an explicit `--allow-raw` or config flag, as flagged in M2.5-REVIEW.md.

## Info Findings

1. **LinkedIn post URLs are optional in the examples but may be expected by verifier.** See Warning #1.
2. **Source confidence scores are sometimes repeated in the post body** (e.g. "Signal is mid. Confidence 55%"). This is acceptable but can feel like metadata leakage; consider moving confidence to newsletter-only.
3. **Signature phrases are defined in `pipeline/voice.py` but rarely appear in outputs.** Either the prompt should encourage them or they should be removed from the voice spec.
4. **`drafting_v2` does not surface fallback metrics.** Operational visibility gap; not a correctness bug.
5. **`pipeline/calendar.py` `_match_score` is heuristic.** Good enough for launch but will mispick on ambiguous titles. Optional LLM rerank is future work.
6. **Sunday post sometimes references real sources the operator reads** (The Batch, Import AI, Interconnects, Simon Willison) even when the underlying item is a synthetic test. This is a prompt-driven hallucination of context, not a factual claim, but worth monitoring.

## Recommended Top 3 Actions

1. **Fix source-URL handling** so drafts either embed the URL or the verifier stops requiring it in the LinkedIn body.
2. **Stabilize newsletter output** with a drafter-side check that `newsletter_section` is ≥ 80 words before saving the draft.
3. **Replace raw hashtag/taxonomy verifier with day-specific hashtag expectations** from `config.calendar.DayPlan` so specific, useful tags pass the gate.
