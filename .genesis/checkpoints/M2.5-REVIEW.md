# M2.5 Review — 7-day content calendar + LLM humanizer + Founder Signal

**Date:** 2026-08-23
**Reviewer:** L1 build context
**Scope:** `config/calendar.py`, `pipeline/calendar.py`, `pipeline/voice.py`, `pipeline/drafting_v2.py`, `pipeline/hermes.py`, `mcp_server.py`, plus tests.

## Critical findings

_None. No source-level security, trust-boundary, or data-loss issues were introduced by this milestone._

## Warning findings

1. **`pipeline/calendar.py` scoring is heuristic.** The `_match_score` function ranks items against the day plan using keyword frequency and source-name matching. It does not use embeddings or the taxonomy model, so it can mispick items when titles/summaries are ambiguous. **Action:** Add an optional LLM-based rerank pass for high-stakes days (Saturday Founder Signal).
2. **`draft_item_v2` silently falls back to rule-based drafting.** If the LLM is reachable but returns malformed JSON, the fallback produces a generic post. In production this could go unnoticed and flood the queue with same-sounding content. **Action:** Surface a metric/warning when fallback rate exceeds a threshold.
3. **`cmd_draft_today` falls back from `worthy` to all raw items.** This makes the demo work with an empty pipeline, but in an automated daily run it could draft low-signal items. **Action:** Gate the raw fallback behind `--allow-raw` or a config flag.

## Info findings

1. **Founder Signal CTA is enforced at hydration time.** `drafting_v2._hydrate_draft` appends the founder question if the post does not end with `?`, satisfying the Saturday requirement.
2. **Voice config is centralized.** `pipeline/voice.py` captures persona, tone, no-go words, signature phrases, per-day word budgets, and CTAs. Future A/B tests can swap `DEFAULT_VOICE` for variants.
3. **Calendar day types are locked in `config/calendar.py`.** Monday–Sunday map to tool_drop, viral_explained, pattern_spotting, builder_memo, security_signal, founder_signal, tomorrow_in_ai.
4. **MCP server gained `draft_today` and keeps auth.** `mcp_server.py` exposes the new tool and still uses `_require_auth` for existing state-changing tools.
