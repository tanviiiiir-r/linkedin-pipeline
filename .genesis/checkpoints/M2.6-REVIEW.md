## Findings

### [Warning-1] Planned fallback threshold originally tuned to test fixture — RESOLVED
**File:** `pipeline/calendar.py`
**Lines:** planned fallback threshold (`planned_threshold = max(0, threshold - 35)`)
**Issue:** The planned threshold is lowered by a fixed 35-point discount to make the current test fixture pass. A planned item with low day-match (rank 4) is accepted because the default threshold is 35, resulting in `planned_threshold = 0`. This risks accepting poorly matched planned items in production.
**Action:** ✅ Applied both: added `RECENCY_POLICY['planned_selection_floor']` (default 10) in `config/settings.py` and updated `select_for_day` to use `max(planned_selection_floor, threshold - 20)`. Test fixture seeded with a stronger day-type match.

### [Warning-2] Generic engagement bonus in `freshness.py` bypasses source floor checks — RESOLVED
**File:** `pipeline/freshness.py`
**Lines:** generic engagement fallback block
**Issue:** The fallback adds up to +25 points for any item with `score`/`comments` metadata, even if the source does not have configured floors. This is intentional for RSS/HN but is not capped per source and could over-boost low-signal items that happened to carry arbitrary engagement fields.
**Action:** Consider limiting the generic bonus to `source_type in {"rss", "hackernews", "news"}` or clamping the maximum to a smaller value (e.g., +15) unless the source has explicit floors.

### [Info-1] `_match_score` does not use topic overlap beyond pillar equality
**File:** `pipeline/calendar.py`
**Issue:** `_match_score` rewards keyword overlap with the day lens and source bias, but does not compare extracted `topics` against the day plan. A day-specific topic boost could improve pattern-spotting/security-signal selection.
**Action:** Future enhancement: add a topic-overlap bonus when `score.topics` intersects with expected topics for the day type.

### [Info-2] `founder_signal` scoring only uses keyword matching
**File:** `pipeline/scoring.py`
**Issue:** The founder pillar is detected via keyword list with a wedge/gtm/moat bonus. It does not incorporate taxonomy topics or source bias. Long-term, founder-signal topics could be added to `pipeline/topics.py` for more robust detection.
**Action:** Add founder-relevant tags (e.g., `founder-insight`, `gtm`, `pricing`) to `TAXONOMY` and reward them in `_best_pillar`.

### [Info-3] M2.6 success criteria mentions stale evergreen demotion but `STALE_EVERGREEN_TERMS` only contains "mcp"
**File:** `config/settings.py`
**Issue:** The single term is a good start, but other evergreen terms (e.g., "prompt engineering", "ai agents", "rag") may resurface. The mechanism is sound; the list should be expanded based on observed bad selections.
**Action:** Monitor future selections and add recurring evergreen offenders to `STALE_EVERGREEN_TERMS`.
