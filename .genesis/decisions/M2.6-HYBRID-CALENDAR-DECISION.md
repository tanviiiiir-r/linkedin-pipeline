# Decision: Hybrid Calendar + Freshness-First Selection

**Date:** 2026-08-24
**Milestone:** M2.6 (extends M2.5)
**Branch:** `codex/hybrid-calendar-v3`

## Problem statement

The existing `select_for_today` picks the highest-scoring item from the raw queue with no hard recency floor and no fallback when the market is quiet. The result: stale evergreen topics like "MCP" keep surfacing because the keyword/topic taxonomy rewards them, and the 7-day calendar forces a daily post even when no strong signal exists.

## Chosen strategy: Option C — Hybrid

1. **Freshness-first breaking queue** — items collected in the last 24–48h, filtered by source-specific recency and engagement velocity.
2. **Planned evergreen queue** — one week ahead, day-type matched, with a freshness half-life; used when no breaking signal is strong enough.
3. **Daily selector** — choose a breaking signal if it clears quality gates; otherwise pull the best planned evergreen slot.
4. **Daily analysis run** — before approval, score relevance/accuracy/perfection and propose `keep`, `update_source`, `rewrite_draft`, `skip`, or `swap_for_breaking`.
5. **Human gate preserved** — no auto-publish; operator approves the final draft.

## Source-specific freshness policy (draft)

| Source type | Max age | Engagement floor | Notes |
|---|---|---|---|
| Hacker News / RSS news | 24h | front-page or ≥50 points | Use HN Algolia front-page + time filter |
| Reddit | 48h | ≥30 upvotes OR ≥10 comments | `top/week` is OK if engagement is high |
| GitHub trending | 72h | trending today | Has no real timestamp; treat as daily snapshot |
| GitHub search | 72h | ≥10 stars/day since creation | creation date filter already used |
| YouTube | 72h | no hard floor | latest channel videos only |
| Instagram | 48h | optional | connected user's media |
| Big-tech blogs | 72h | none | RSS timestamps |

## Data model changes needed

- Add `published_at` and `collected_at` to all items (some GitHub items are missing).
- Add `engagement` JSON/dict per source (points, comments, stars, score, velocity).
- Add `queue_type` enum: `breaking`, `planned`, `manual`.
- Add `expires_at` to planned items (freshness half-life).

## Selection scoring changes needed

- Penalize age exponentially after 24h.
- Penalize stale evergreen keywords ("MCP") unless the surrounding context is clearly recent (published in last 48h, mentions a specific new release/repo).
- Add source velocity bonus (points/hour, stars/day).
- Return `None` / empty list if no item clears a minimum score; dashboard shows "No strong signal today — choose from planned queue or inject manually."

## Files to modify

- `config/settings.py` — recency policy constants, engagement floors.
- `config/calendar.py` — add `freshness_half_life_hours`, `evergreen_ok` flag per day plan.
- `pipeline/calendar.py` — hybrid selector, breaking vs planned, no-signal path.
- `pipeline/scoring.py` — age penalty, evergreen keyword demotion, velocity bonus.
- `pipeline/hermes.py` — collect `published_at` everywhere, add recency filter.
- `pipeline/collectors/reddit.py`, `youtube.py`, `instagram.py` — return engagement + timestamp.
- `pipeline/content_analyst.py` — integrate recency into relevance score; add swap logic.
- `pipeline/review_dashboard.py` + `review_server.py` — show queue type, age, engagement, "swap with breaking" action.
- Tests + docs.

## L1 build plan

1. Add policy constants and update `Item` model with `engagement`, `queue_type`, `expires_at`.
2. Implement recency gating in collectors and normalize timestamps.
3. Rewrite `select_for_today` with hybrid logic.
4. Update `content_analyst.py` daily analysis with swap recommendation.
5. Update dashboard to display queue type + freshness + swap action.
6. Add tests.
7. Run ruff + pytest.
8. L4 review.
9. Push.

## Out of scope

- Fully automated publish.
- Scraping X/Twitter or OpenAI/Anthropic.
- Real-time trend velocity from web search APIs.
