# M2.6 Implementation Plan — Hybrid Calendar + Freshness-First Selection

**Branch:** `codex/hybrid-calendar-v3`  
**Goal:** Stop the pipeline from drafting stale evergreen posts, and give it a planned-evergreen fallback when the market is quiet.

## Phase 1 — Data model + policy constants

Files: `config/settings.py`, `pipeline/storage.py`, tests `test_storage.py`

- Add `Item` fields:
  - `queue_type: str` default `"breaking"` (`breaking`, `planned`, `manual`)
  - `expires_at: str = ""`
  - `engagement: dict` default `{}` (structured per source)
- Add SQLite columns with migration guards.
- Add `RECENCY_POLICY` constants:
  - `BREAKING_MAX_AGE_HOURS` default 48
  - `PLANNED_HALF_LIFE_HOURS` default 168 (1 week)
  - per-source age and engagement floors
- Add `STALE_EVERGREEN_TERMS = ["mcp"]` with age-aware demotion.

## Phase 2 — Recency gating in collectors

Files: `pipeline/hermes.py`, `pipeline/collectors/*.py`

- Normalize `published_at` and `collected_at` for every item.
- Add `engagement` dict from each source:
  - Reddit: `score`, `comments`, `upvote_velocity`
  - YouTube: `publishedAt` only for now (views not available via Composio)
  - Instagram: timestamp only
  - GitHub search: `stars`, `stars_per_day`
  - GitHub trending: set `collected_at` only, mark as breaking_daily
  - RSS: parse `published`, fallback to `collected_at`
- Add recency filter helper in `pipeline/hermes.py`:
  - reject items older than source max age.
  - reject items below source engagement floor.
  - log rejected reason (no silent pass).

## Phase 3 — Hybrid selection scoring

Files: `pipeline/calendar.py`, `pipeline/scoring.py`, `config/calendar.py`

- Rewrite `_match_score` to:
  - penalize age with an exponential decay after 24h
  - demote stale evergreen terms unless item age < 48h and has a specific new release/repo signal
  - add engagement velocity bonus
  - add source recency bonus
- Add `select_for_today` modes:
  - `mode="breaking"` (default): only items passing freshness + engagement gates
  - `mode="planned"`: items with `queue_type="planned"` not expired
  - `mode="hybrid"`: best breaking if score ≥ threshold, else best planned
- Add `Item.is_fresh()` helper.
- Add explicit `NO_STRONG_SIGNAL` return when nothing clears threshold; dashboard shows manual fallback.

## Phase 4 — Daily analysis / swap recommendation

Files: `pipeline/content_analyst.py`, `pipeline/review_dashboard.py`

- Add `swap_for_breaking` proposed action when a breaking item is fresher and higher-scored than the queued planned item.
- Surface queue type, age, engagement in dashboard.
- Add API endpoint `POST /api/swap` to replace a planned draft with a breaking item (operator approval).

## Phase 5 — CLI + integration

Files: `pipeline/hermes.py`, `run.py`

- Add `--allow-planned` and `--allow-manual` flags to `draft-today`.
- Default `draft-today` requires breaking signal; falls back to planned only with flag.
- Add `cmd_plan_content` to seed planned evergreen items from operator input or curated source list.
- Wire daily run: collect → score → analyze → draft-today --hybrid.

## Phase 6 — Tests + review

- Add `test_calendar.py` cases for:
  - stale item rejected
  - evergreen demotion
  - planned fallback
  - no-signal path
  - engagement velocity bonus
- Add `test_scoring.py` cases for age penalty and stale-term demotion.
- Add `test_hermes.py` recency filter tests (mocked).
- Run `ruff`, `pytest`, `bandit`.
- L4 review.
- Push.

## Demo commands

```bash
python run.py draft-today --dry-run              # default: breaking-only
python run.py draft-today --dry-run --hybrid     # hybrid: breaking else planned
python run.py analyze-content --date 2026-08-24  # daily relevance/perfection report
python -m pytest tests/test_calendar.py tests/test_scoring.py tests/test_hermes.py -q
```

## Success criteria

- Stale MCP/old evergreen items no longer auto-selected.
- A quiet market does not force a bad post; planned queue is used or operator is notified.
- Every collected item has a clear `published_at` / `collected_at` and per-source recency check.
- All new code is covered by tests; ruff and pytest pass.
- L4 review approves.

## Out of scope

- Real-time web search trend APIs.
- Automated LinkedIn image generation.
- Publishing automation (still human-gated).
